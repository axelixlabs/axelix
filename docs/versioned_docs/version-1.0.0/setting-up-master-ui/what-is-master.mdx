# What is Master?

Axelix Master (or simply "Master") is the central hub of the Axelix ecosystem, application with enhanced capabilities
for managing and monitoring Spring Boot applications across various environments.

## Core Purpose

Axelix Master serves as a **centralized management console** that automatically discovers, registers, and monitors
Spring Boot applications, providing real-time insights and control.

## Key Capabilities

### 🔍 **Service Discovery**
Master learns about Spring Boot applications through two complementary mechanisms:

**Self-registration (any environment):**
Applications that include the Axelix Spring Boot Starter announce themselves to Master and send periodic heartbeats. This
works anywhere the app can reach Master — Docker Compose, bare-metal, VMs, Kubernetes, etc. It is **opt-in per
application**: enable it on in your application with `axelix.sbs.discovery.self-registration=true` (it is off by default). Master
accepts these registrations out of the box (`axelix.master.discovery.self-registration.enabled` setting in Master on by default).

**Automatic discovery (Kubernetes only):**
When enabled (controlled by `axelix.master.discovery.auto.enabled` property), Master actively scans the platform to find qualifying services.
Platform scanning is currently implemented for **Kubernetes** only. It is off by default in Master's own configuration,
but the official [Helm chart](https://github.com/axelixlabs/helm-charts/) turns it on by default.

**How discovery works:**
1. **Self-registration**: apps with the Axelix Starter register themselves and heartbeat
2. **Platform scanning** (Kubernetes): Master probes the cluster for services exposing Axelix SBS endpoints
3. **Health monitoring**: Master periodically polls registered instances and evicts ones that stop heartbeating
