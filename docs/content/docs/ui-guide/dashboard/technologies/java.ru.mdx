В парке из десятков сервисов сложно понять, какие из них уже ускоряют старт с помощью AppCDS или AOT cache, какой
сборщик мусора у каждого и где включено GC-логирование. Дашборд Java отвечает на это сразу для всего парка.

Страница доступна только для чтения всем пользователям, прошедшим аутентификацию: ее могут открыть `VIEWER`, `EDITOR`,
`ADMIN` и `SUPER_ADMIN`. Полную матрицу ролей и полномочий см. в разделе [Роли и
полномочия](../../../setting-up-master-ui/authentication/authentication.mdx#роли-и-полномочия).

## Что показывает страница

Для каждой возможности JVM страница показывает долю сервисов, которые её используют:

- **Project Leyden**: сервисы, которые стартуют с AppCDS (`-XX:SharedArchiveFile`) или с AOT cache (`-XX:AOTCache`),
  по отдельности и вместе.
- **Сборщики мусора**: какой сборщик мусора у какой доли сервисов, например G1, Parallel или ZGC. Самый
  распространённый выделен отдельно.
- **GC-логирование**: сервисы, где GC-логирование включено прямо сейчас, в том числе включённое из Axelix. См. раздел
  [Включение GC-логирования](../../../features/jvm/garbage-collector.mdx#включение-gc-логирования).
- **Project Lilliput**: сервисы с компактными заголовками объектов (`-XX:+UseCompactObjectHeaders`).

## Как это работает

Дашборд считает то, что каждый сервис сообщает о своей JVM. Master записывает это раз в день и использует последнюю
запись. Сервис учитывается один раз, сколько бы у него ни было инстансов.
