***Дашборд Persistence в интерфейсе Axelix***

Запросы N+1 и пагинация в памяти не ломают приложение, но стоят лишних запросов и памяти.
[Мониторинг транзакций](../../../features/spring-framework/transaction-control.mdx) показывает их для одного сервиса.
Дашборд Persistence показывает, где в парке их больше всего, чтобы было видно, на какие сервисы смотреть в первую
очередь.

Страница доступна только для чтения всем пользователям, прошедшим аутентификацию: ее могут открыть `VIEWER`, `EDITOR`,
`ADMIN` и `SUPER_ADMIN`. Полную матрицу ролей и полномочий см. в разделе [Роли и
полномочия](../../../setting-up-master-ui/authentication/authentication.mdx#роли-и-полномочия).

## Что показывает страница

Страница показывает две проблемы рядом:

- **N+1**: ленивая ассоциация загружается отдельным запросом для каждой записи.
- **Пагинация в памяти**: Hibernate загружает весь результат и вырезает страницу в памяти.

Для каждой проблемы видно:

- сколько случаев во всём парке;
- в каком сервисе их больше всего;
- как случаи распределены по сервисам.

Сервисы без случаев не показываются. Подробнее о каждой проблеме см. в разделе [Обнаруженные
проблемы](../../../features/spring-framework/transaction-control.mdx#обнаруженные-проблемы) Мониторинга транзакций.

## Как это работает

Дашборд считает то, что Мониторинг транзакций нашёл в каждом сервисе. Master записывает это раз в день и использует
последнюю запись. Сервис учитывается один раз, сколько бы у него ни было инстансов.

Данные появляются только для сервисов с Hibernate и включённым мониторингом транзакций. См. раздел
[Свойства](../../../features/spring-framework/transaction-control.mdx#свойства) Мониторинга транзакций.
