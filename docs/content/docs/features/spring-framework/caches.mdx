***Caches page as presented in Axelix UI***

A cache that returns stale data or rarely hits is hard to spot from the outside: the application keeps working, just
wrongly or slowly. The Caches page shows how each cache performs and lets you clear it or turn it off without a
restart.

The page is available to every authenticated user: **VIEWER**, **EDITOR**, **ADMIN**, and **SUPER_ADMIN** can all open
it and inspect cache statistics. Clearing a cache requires the `caches:clear` authority, and turning a cache on or off
requires `caches:toggle`. Both are granted by the built-in **EDITOR**, **ADMIN**, and **SUPER_ADMIN** roles. Users
without them see the same controls, but Axelix keeps them disabled and explains why in a tooltip on hover. See [Roles
and authorities](../../setting-up-master-ui/authentication/authentication.mdx#roles-and-authorities) for the full
role/authority matrix.

## What the page shows

The page lists the caches grouped by cache manager. For each cache, you see its name and the class of the native cache
behind it, for example `java.util.concurrent.ConcurrentHashMap` for a `ConcurrentMapCache`. You can search
the list by cache name or cache manager name.

## Cache details

<ScreenshotsNotice text="Screenshots show the latest minor release of Axelix.">

![caches details page](/img/feature/caches/caches-details-page.png)

</ScreenshotsNotice>

***Cache details page as presented in Axelix UI***

When the application has looked up a cache at least once, you can expand it to see how well it works. Caches without
recorded lookups stay in the list but cannot be expanded.

The **Hits/Total Ratio** chart shows the share of hits over time, from 0 to 1. A ratio that stays low means most
lookups miss, so the cache costs memory without saving much work. Hover the chart to see the exact ratio at a point in
time.

Below the chart, **Statistics** sums up the recorded lookups:

- **Hits** and **Misses**: how many lookups found a value and how many did not, with their share of all lookups.
- **Entries count**: the estimated number of entries in the cache. It appears only when the cache can report its size,
  which is currently Caffeine `Cache` and caches backed by `ConcurrentHashMap`, such as `ConcurrentMapCache`.

## Managing caches

Each action below asks for confirmation before it changes the running application.

### Clear a cache

Clear a cache when it holds stale data, for example after you changed a record directly in the database. Click
**Clear** next to a cache to remove all its entries, or **Clear All Caches** to empty every cache of the application.
The application fills the caches again on the next lookups.

### Enable or disable a cache

Use the **Status** switch to turn a cache off at runtime. While a cache is off, every lookup misses and new values are
not stored, so the application gets the data from the source on every call. This helps to check whether a bug comes
from cached data. Switch the cache back on to resume caching.

## Manage caches on several instances

<ReleasedInNotice version="1.3.0" />

Each replica of an application keeps its own copy of a cache, so clearing it on one replica leaves stale entries on
the others. Open **Instances** next to the search field to choose which instances of the application an action
applies to. The list shows each instance with its commit and status.

The instance you opened is always included and cannot be deselected. Check other instances one by one, or use
**Select all other instances**. The button shows how many instances are selected, or **All** when every instance is.

The selection applies to every action on the page: **Clear All Caches**, clearing a single cache, and the **Status**
switch. If some of the selected instances cannot be reached, the action still applies to the rest. The statistics on
the page always belong to the instance you opened.

The selector appears only when the application has more than one instance. It resets to the current instance when you
switch to another instance.

## MCP Tools

Caches can also be inspected and cleared by an AI agent through MCP. See the [MCP Tools

## Properties

Cache management is enabled by default. To turn it off entirely, set `axelix.sbs.cache.management.enabled=false`. See
[Cache management](../../setting-up-spring-boot-service/spring-boot-starter/configuration.mdx#cache-management) for
details.

## Enable Dedicated Actuator Endpoint

<LegacyNotice
  version="1.2.0"
  reason={<>If you are on Axelix 1.2.0 or later, none of this is required: the starter registers its custom actuator
    endpoints by itself, and Axelix no longer requires the <code>health</code>/<code>info</code> endpoints to be
    enabled. It works perfectly well without them. No configuration is needed here.</>}

The page is backed by the `axelix-caches` actuator endpoint contributed by the Axelix Spring Boot Starter. Expose it
through the standard Spring Boot Actuator properties. See [Configuring Spring Boot
Starter](../../setting-up-spring-boot-service/spring-boot-starter/configuration.mdx) for the full list
of Axelix endpoints and surrounding setup:

<Tabs groupId="spring-config" items={['application.properties', 'application.yaml']}>
  <Tab value="application.properties">

```properties
management.endpoints.web.exposure.include=axelix-caches
```

  </Tab>
  <Tab value="application.yaml">

```yaml
management:
  endpoints:
    web:
      exposure:
        include:
          - axelix-caches
```

  </Tab>
</Tabs>
