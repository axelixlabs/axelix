***Запланированные задачи в интерфейсе Axelix***

Задача `@Scheduled` работает в фоне, поэтому никто не замечает, что она начала падать или замедляться, пока не пропадут
результаты её работы. Эта страница показывает все запланированные задачи сервиса и то, как прошли их последние запуски.
Кроме того, здесь можно поменять расписание задачи без передеплоя.

Чтобы включать и выключать задачи, менять триггер и запускать задачу вручную, нужно полномочие `scheduled-tasks:write`.
Его дают встроенные роли **EDITOR**, **ADMIN** и **SUPER_ADMIN**. Пользователи без этого полномочия видят те же элементы
управления, но Axelix оставляет их неактивными и объясняет причину в подсказке при наведении.

## Что показывает страница

Задачи на странице сгруппированы по типу триггера:

- **Cron**: задача запускается в моменты, которые описывает cron-выражение, например `0 0/15 9-17 * * MON-FRI`.
- **Fixed delay**: задача ждёт заданный интервал после окончания каждого запуска, поэтому запуски никогда не
  пересекаются.
- **Fixed rate**: задача стартует через заданный интервал, отсчитанный от начала предыдущего запуска.

Список можно искать по имени класса или метода. Рядом с каждой задачей страница показывает долю успешных запусков по
сохранённой истории, поэтому падающая задача заметна сразу, без перехода в неё. Доля от 90% считается нормальной.
Выключенные задачи вместо доли показывают **ВЫКЛ**.

Когда вы выбираете задачу, страница показывает полное имя её класса и расписание обычными словами, например «Каждые
3 секунды». Для cron-задачи рядом с описанием видно и само выражение.

## История запусков

<ReleasedInNotice version="1.3.0" />

Axelix записывает каждый запуск задачи: и по расписанию, и по кнопке **Запустить**. Master собирает запуски со всех
инстансов сервиса, так что история задачи общая для всех инстансов. Сводка считается по всем сохранённым запускам:

- **Последний запуск**: сколько времени назад начался последний запуск.
- **Успешно**: доля запусков, которые завершились без исключения.
- **Ошибки**: число запусков, в которых было выброшено исключение.
- **Среднее** и **p95**: средняя длительность запуска и длительность, в которую укладываются 95% запусков. Если p95
  намного больше среднего, значит, некоторые запуски время от времени зависают.

График **Длительность** показывает последние 30 запусков от старых к новым и отмечает упавшие. Высота столбика
нелинейна, поэтому короткие запуски остаются заметны рядом с одним медленным. При наведении на столбик видно, когда
начался запуск, сколько он длился и, если он упал, тип ошибки.

Если задача падала, блок **Ошибки по типу** группирует сбои по классу исключения, самые частые сверху. Для каждой группы
видно последнее сообщение об ошибке и когда она произошла. Так сразу понятно, повторяется ли одна причина или сбои не
связаны между собой.

Таблица **Запуски** показывает те же последние 30 запусков: время начала, инстанс, на котором выполнялась задача,
длительность и результат. Переключитесь на **Ошибки**, чтобы оставить только упавшие запуски.

Пока страница открыта, история сама не обновляется. Чтобы увидеть новые запуски, выберите задачу заново. Пока Master не
получил ни одного запуска задачи, вместо истории страница показывает **Нет данных о запусках этой задачи**.

### Хранение истории запусков

Master хранит историю в своей базе данных и удаляет старые запуски по расписанию. Сколько истории он хранит, задают
свойства Master (см. также [Настройка
Master](../../setting-up-master-ui/configuring-master/configuring-master.mdx#история-запланированных-задач)):

| Свойство                                                        | По умолчанию     | Описание                                                                        |
|-----------------------------------------------------------------|------------------|---------------------------------------------------------------------------------|
| `axelix.master.scheduled-tasks.history.retention`               | `30d`            | Сколько Master хранит запуск. Более старые запуски удаляются при следующей очистке. |
| `axelix.master.scheduled-tasks.history.max-executions-per-task` | `50`             | Сколько последних запусков Master хранит для каждой задачи.                     |
| `axelix.master.scheduled-tasks.history.cleanup.schedule`        | `0 */10 * * * *` | Cron-выражение для задачи очистки. По умолчанию она запускается каждые 10 минут. |

<Tabs groupId="spring-config" items={['application.properties', 'application.yaml']}>
  <Tab value="application.properties">

```properties
axelix.master.scheduled-tasks.history.retention=7d
axelix.master.scheduled-tasks.history.max-executions-per-task=100
```

  </Tab>
  <Tab value="application.yaml">

```yaml
axelix:
  master:
    scheduled-tasks:
      history:
        retention: 7d
        max-executions-per-task: 100
```

  </Tab>
</Tabs>

## Управление задачами

Эти действия применяются к открытому инстансу. Остальные инстансы того же сервиса сохраняют своё состояние и
расписание.

### Включение и выключение задачи

Переключатель **ВКЛ** / **ВЫКЛ** останавливает запуски задачи по расписанию, например на время обслуживания внешней
системы. Сначала Axelix просит подтвердить действие. Если выключить задачу во время запуска, запуск доработает до конца,
а дальше задача будет игнорировать расписание. Чтобы вернуть запуски по расписанию, переключите её обратно на **ВКЛ**.

### Изменение триггера

Нажмите **Изменить триггер**, чтобы поменять, когда запускается задача. Новое расписание начинает действовать сразу, без
перезапуска приложения.

- Для cron-задачи введите новое выражение из шести полей: секунда, минута, час, день, месяц, день недели. Axelix
  проверяет выражение прямо при вводе. Превью показывает, когда задача будет запускаться (**Запуск:**), или что не так с
  выражением (**Ошибка:**).
- Для задачи fixed delay или fixed rate введите новый интервал целым числом миллисекунд больше 0.

Кнопка **Применить триггер** неактивна, пока значение не станет корректным и не будет отличаться от текущего.

### Запуск задачи вручную

Нажмите **Запустить** и подтвердите, чтобы выполнить задачу один раз прямо сейчас. Расписание при этом не меняется,
поэтому так удобно повторить упавшую задачу или проверить исправление, не дожидаясь следующего запуска.

## Включите Нужный Actuator Ендпоинт

<LegacyNotice
  version="1.2.0"
  reason={<>Если вы используете Axelix 1.2.0 или новее, ничего из этого не требуется: стартер сам регистрирует свои
    actuator-эндпоинты, а эндпоинты <code>health</code>/<code>info</code> Axelix больше не требуются — он отлично
    работает и без них. Никакая настройка здесь не нужна.</>}
/>

Страница работает поверх actuator-эндпоинта `axelix-scheduled-tasks`, который добавляет Axelix Spring Boot Starter. Она
доступна через стандартные свойства Spring Boot Actuator. Полный список конечных точек Axelix и сопутствующих настроек
см. в разделе [Настройка Spring Boot
Starter](../../setting-up-spring-boot-service/spring-boot-starter/configuration.mdx):

<Tabs groupId="spring-config" items={['application.properties', 'application.yaml']}>
  <Tab value="application.properties">

```properties
management.endpoints.web.exposure.include=axelix-scheduled-tasks
```

  </Tab>
  <Tab value="application.yaml">

```yaml
management:
  endpoints:
    web:
      exposure:
        include:
          - axelix-scheduled-tasks
```

  </Tab>
</Tabs>
