***Details page as presented in Axelix UI***

The page is available to every authenticated user: **VIEWER**, **EDITOR**, **ADMIN**, and **SUPER_ADMIN** can all open
it and trigger the **Download state** export. Note that the environment-properties and configuration-properties files
inside the exported archive are still subject to the per-page authority masking: callers without `environment.values:read` /
`config-properties.values:read` get `******` for those values. See [Roles and
authorities](../../setting-up-master-ui/authentication/authentication.mdx#roles-and-authorities) for the full
role/authority matrix.

## Service Information Inner Header
- **Instance Name**: The name of the application instance. The postfix may vary depending on the runtime
and discovery environment of Axelix Master.
- **Download state**: exports the state of the instance as one `.zip` file, so you can analyze a problem later or
  attach it to a bug report.

### Download state Components
In the dialog, you choose what to include. The items are grouped into **JVM** and **Spring**:

- **Heap Dump**: every object in memory, as an `.hprof` file. For memory leaks.
- **Thread Dump**: stack traces of all threads. For hangs and contention.
- **Beans**: all beans with their scope, type, and dependencies.
- **Caches**: cache managers and caches.
- **Conditions**: why each auto-configuration did or did not apply.
- **Configuration Properties**: `@ConfigurationProperties` beans and their bound values, with sensitive values masked.
- **Environment**: property sources in order of precedence, with sensitive values masked.
- **Scheduled Tasks**: cron, fixed-rate, and fixed-delay tasks.

Before you download, the dialog shows the estimated size of the archive. Every item except the heap dump takes less
than 1 MB. The heap dump is about as large as the used heap, often hundreds of MB, and the application stops
responding while it is written. The heap dump also holds everything in memory, including passwords and tokens, so
store it like a credential.

#### Heap dump access

<ReleasedInNotice version="1.3.0" />

Starting with Axelix 1.3.0, exporting a heap dump as part of the application state requires the `heap-dump:read`
authority. Without it, this option is disabled, but you can still export the other components. `ADMIN` and
`SUPER_ADMIN` hold this authority by default.

## Git Information

| Field                | Description              | Example                |
|----------------------|--------------------------|------------------------|
| **Commit SHA**         | Short commit hash        | `a1b2c3d`              |
| **Branch**             | Git branch name          | `main`                 |
| **Commit's Author**    | Commit author name       | `John Doe`             |
| **Author's Email**     | Commit author email      | `john@example.com`     |

## Build Information

| Field          | Description                    | Example                       |
|----------------|--------------------------------|-------------------------------|

| **JDK Vendor**        | Java distribution vendor                           | `Liberica`, `OpenJDK`, `Amazon Corretto`  |

Spring ecosystem versions:

| Field                        | Description                    | Example    |
|------------------------------|--------------------------------|------------|
| **Spring Boot**              | Spring Boot framework version  | `3.3.0`    |

## Operating System Information
System-level details:

| Field                | Description                                   | Example                   |
|----------------------|-----------------------------------------------|---------------------------|
| **OS Family**        | Operating system name                         | `Linux`, `Windows Server` |
| **Kernel Version**   | Operating system version                      | `6.12.96`, `2022`         |
| **CPU Architecture** | CPU architecture                              | `amd64`, `arm64`          |
| **PID**              | ID of the application's process               | `1`                       |
| **Process User**     | OS user the application's process runs as     | `root`, `app`             |

**PID** and **Process User** appear starting with Axelix 1.3.0. A process running as `root` inside a container is
worth a second look, because it has more rights than the application needs.

## Enable Dedicated Actuator Endpoint

<LegacyNotice
  version="1.2.0"
  reason={<>If you are on Axelix 1.2.0 or later, none of this is required: the starter registers its custom actuator
    endpoints by itself, and Axelix no longer requires the <code>health</code>/<code>info</code> endpoints to be
    enabled: it works perfectly well without them. No configuration is needed here.</>}
/>

The page is backed by the `axelix-details` actuator endpoint contributed by the Axelix Spring Boot Starter. Expose it
through the standard Spring Boot Actuator properties: see [Configuring Spring Boot
Starter](../../setting-up-spring-boot-service/spring-boot-starter/configuration.mdx) for the full list
of Axelix endpoints and surrounding setup:

<Tabs groupId="spring-config" items={['application.properties', 'application.yaml']}>
  <Tab value="application.properties">

```properties
management.endpoints.web.exposure.include=axelix-details
```

  </Tab>
  <Tab value="application.yaml">

```yaml
management:
  endpoints:
    web:
      exposure:
        include:
          - axelix-details
```

  </Tab>
</Tabs>
