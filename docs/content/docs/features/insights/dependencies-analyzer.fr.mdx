***Dependencies Analyzer dans l’interface Axelix***

Une application intègre des dizaines de bibliothèques, la plupart de manière transitive. Le fichier de build ne vous indique pas
lesquelles sont abandonnées ou en mode maintenance et ne bénéficieront plus de correctifs de sécurité. Il ne vous indique pas non plus
si la ligne de versions de Spring Boot (une branche de version mineure telle que `3.5.x`) sur laquelle l’application s’exécute reçoit
encore des mises à jour OSS. Dependencies Analyzer présente ces deux informations pour une instance donnée.

Cette page est en lecture seule et accessible à tout utilisateur authentifié : **VIEWER**, **EDITOR**, **ADMIN** et **SUPER_ADMIN**
peuvent tous l’ouvrir. Consultez [Rôles et autorités](../../setting-up-master-ui/authentication/authentication.mdx#rôles-et-autorités)
pour obtenir la matrice complète des rôles et des autorités.

## Ce que montre la page

La [fenêtre de support de Spring Boot](https://spring.io/projects/spring-boot#support) apparaît en premier. Elle indique la ligne de
versions de Spring Boot utilisée par l’instance, la date à laquelle le [support OSS](https://spring.io/support-policy) de cette ligne
se termine ou s’est terminé, la disponibilité d’un support commercial, la durée depuis la fin du support OSS de cette ligne et la ligne
la plus proche qui est encore prise en charge. Une fois le support OSS terminé, la ligne ne bénéficie plus de nouvelles versions OSS,
y compris de correctifs de sécurité : les [CVE](https://en.wikipedia.org/wiki/Common_Vulnerabilities_and_Exposures) sont corrigées
uniquement dans le cadre d’un abonnement commercial.

En dessous, la page répertorie chaque bibliothèque du classpath d’exécution avec sa version et précise si elle est déclarée directement
dans le fichier de build ou intégrée de manière transitive. Les projets qui ne sont plus activement développés sont signalés :

- **Maintenance mode** : le développement de fonctionnalités est arrêté et les versions ne contiennent plus que des correctifs critiques.
- **Dormant** : aucune version n’a été publiée depuis longtemps, mais les auteurs n’ont fait aucune annonce. Contrairement aux autres
  statuts, celui-ci correspond à ce qu’Axelix observe, et non à une déclaration des auteurs.
- **Discontinued** : le projet est terminé. Aucune nouvelle version d’aucune sorte n’est prévue, y compris pour des correctifs de sécurité.

Dépliez une bibliothèque pour afficher :

- Le chemin entre l’application et cette bibliothèque, c’est-à-dire la dépendance directe qui l’a intégrée.
- Le statut de son projet.
- Un lien vers la page amont qui justifie ce statut.

## Fonctionnement

Au moment du build, le [plugin de build Axelix](../../setting-up-spring-boot-service/build-plugin/configuration.mdx) écrit le graphe
des dépendances d’exécution de l’application dans son archive sous la forme d’un SBOM CycloneDX. L’Axelix Spring Boot Starter fournit
ce fichier à Master. Lorsque vous ouvrez la page, Master compare les bibliothèques à son catalogue de projets et à ses données sur les
lignes de versions de Spring Boot.

Une bibliothèque dont le projet ne figure pas dans le catalogue est affichée sans statut. Cela signifie qu’Axelix ne formule aucune
affirmation à son sujet, et non que le projet est en bonne santé.

La page est affichée pour les instances utilisant la version 1.2.0 ou ultérieure du [starter](../../setting-up-spring-boot-service/spring-boot-starter/configuration.mdx)
Axelix. Avec des starters plus anciens, elle n’apparaît pas dans la barre latérale du [profil de service](../../ui-guide/service-profile.mdx).
Le SBOM provient de la version 1.2.0 ou ultérieure du [plugin de build](../../setting-up-spring-boot-service/build-plugin/configuration.mdx).
Pour effectuer la mise à niveau, consultez [Mise à niveau d’Axelix](../../more/upgrading.mdx).

## Télécharger le SBOM

<ReleasedInNotice version="1.3.0" />

À partir de Master 1.3.0, vous pouvez télécharger le SBOM CycloneDX de l’instance sous le nom `dependencies.cdx.json`. L’instance
doit utiliser la version 1.2.0 ou ultérieure du starter Axelix, et l’application doit être construite avec la version 1.2.0 ou
ultérieure du plugin de build Axelix. La mise à niveau du starter vers la version 1.3.0 n’est pas nécessaire. Vos propres modules du
système de build (Maven / Gradle) sont exclus du graphe.

Un build Gradle ou Maven standard intègre automatiquement le SBOM : aucune configuration supplémentaire n’est donc nécessaire.

Le document ne contient pas encore de données de licence et ne convient donc pas aux audits de licences ou de conformité.
[SBOM de dépendances](../../setting-up-spring-boot-service/build-plugin/what-is-build-plugin.mdx#sbom-des-dépendances-gradle)
décrit le contenu du fichier.
