***Loggers page as presented in Axelix UI***

To investigate a problem on a running service, you often need more detailed logs from one part of it. The Loggers page
lets you raise the level of a logger right away, without changing the configuration or restarting the service, and
then bring it back.

The page is available to every authenticated user: **VIEWER**, **EDITOR**, **ADMIN**, and **SUPER_ADMIN** can all open
it, change levels, and reset levels. See [Roles and
authorities](../../../setting-up-master-ui/authentication/authentication.mdx#roles-and-authorities) for the full
role/authority matrix.

## What the page shows

The page lists all loggers and logger groups of the instance with their current level. A target mark <TargetThemeIcon /> next
to a level means the level is set explicitly for this logger or group, in the application configuration or in Axelix.
A level without the mark is inherited from a parent logger.

You can change the level:

- Of a logger. Its children without their own level inherit the new level: when you switch `com.axelixlabs.axelix`
  from <INFO /> to <DEBUG />, `com.axelixlabs.axelix.sbs` switches to <DEBUG /> as well.
- Of a logger group. The level applies to every logger in the group: setting the `web` group to <WARN /> sets <WARN /> for
  all of its loggers.

The reset button <Image src="/img/feature/loggers/reset.svg" alt="reset icon" width={20} height={20}/> returns a logger to the level it had before you first changed it in Axelix. It works for loggers changed at
runtime: on this page, through MCP, or with a direct request to the `axelix-loggers` actuator endpoint. Logger groups
cannot be reset.

***Setting a temporary logging level in Axelix UI***

When you need verbose logs only for a while, for example to catch a bug, set a temporary level instead and don't worry
about switching it off. Click the timer icon next to the logger, pick the level and the time when it should end. If
that time has already passed today, the level stays until that time tomorrow.

When the time runs out, the logger returns to the level it had before. To end the temporary level early, reset the
logger. Temporary levels are not available for logger groups.

## MCP Tools

Reading the logger tree and changing levels at runtime (for a single logger, a logger group, or resetting an individual
logger) are also exposed to AI agents through MCP. See the [MCP Tools
catalog](../../../setting-up-master-ui/mcp/mcp-tools.mdx#loggers).

## Enable Dedicated Actuator Endpoint

<LegacyNotice
  version="1.2.0"
  reason={<>If you are on Axelix 1.2.0 or later, none of this is required: the starter registers its custom actuator
    endpoints by itself, and Axelix no longer requires the <code>health</code>/<code>info</code> endpoints to be
    enabled — it works perfectly well without them. No configuration is needed here.</>}
/>

The page is backed by the `axelix-loggers` actuator endpoint contributed by the Axelix Spring Boot Starter. Expose it
through the standard Spring Boot Actuator properties — see [Configuring Spring Boot
Starter](../../../setting-up-spring-boot-service/spring-boot-starter/configuration.mdx) for the full
list of Axelix endpoints and surrounding setup:

<Tabs groupId="spring-config" items={['application.properties', 'application.yaml']}>
  <Tab value="application.properties">

```properties
management.endpoints.web.exposure.include=axelix-loggers
```

  </Tab>
  <Tab value="application.yaml">

```yaml
management:
  endpoints:
    web:
      exposure:
        include:
          - axelix-loggers
```

  </Tab>
</Tabs>
