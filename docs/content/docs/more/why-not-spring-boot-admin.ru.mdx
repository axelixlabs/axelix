[Spring Boot Admin](https://github.com/codecentric/spring-boot-admin) (SBA) был одним из первых источников вдохновения для Axelix.
Инженеры, создающие Axelix, много лет использовали SBA в реальных средах. Единый UI для Spring Boot Actuator —
полезная отправная точка, но задачи команд выходят далеко за рамки отображения данных Actuator.

Этот опыт привёл к расширению задач: **Axelix — это AI-native платформа с открытым исходным кодом для разработки и
развития экосистем микросервисов на Java и Spring Boot.** Она охватывает привычные сценарии управления приложениями
со встроенным ролевым контролем доступа, добавляет глубокую диагностику и управление во время работы сервисов,
а также помогает командам управлять изменениями во всей экосистеме. Платформа рассчитана и на инженеров, и на AI-агентов.

## Привычные сценарии управления со встроенным RBAC

Axelix охватывает повседневные сценарии, ради которых команды используют SBA: исследование состояния приложения,
просмотр метрик, смену уровней логирования, изучение конфигурации и работу с кешами. Эти возможности поставляются
со встроенной моделью пользователей и прав доступа.

Master предоставляет локальных пользователей, вход через OAuth2/OIDC, сопоставление ролей и права на отдельные операции.
Например, права определяют возможность очищать кеши, изменять запланированные задачи и читать чувствительные значения свойств.
Master аутентифицирует пользователей и MCP-клиентов, проверяет доступ и использует подписанные JWT при обращении к сервисам.
Модель прав описана в разделе [Аутентификация](../setting-up-master-ui/authentication/authentication.mdx).

SBA предоставляет точки интеграции со Spring Security, но **реализовать и сопровождать интеграцию IAM и правила
авторизации для своего развёртывания должна ваша команда**. Для этого нужно написать конфигурацию безопасности,
связать пользователей с ролями и встроить проверки, определяющие, кто может читать чувствительные данные или выполнять
операции управления. Также нужно защитить Actuator-эндпоинты управляемых приложений.
В [документации SBA по безопасности](https://docs.spring-boot-admin.com/4.1.4/docs/security/) показаны необходимые конфигурация и код.

Интеграция безопасности требует внимания к деталям, и реализовать её правильно не всегда просто. Пропущенная проверка
доступа или неверное сопоставление ролей могут раскрыть чувствительные данные или разрешить нежелательные изменения
в работающих сервисах. Реализация, тестирование и дальнейшее сопровождение этих проверок остаются задачей вашей команды.

**В Axelix эта модель безопасности входит в продукт.** Управление пользователями, интеграция с провайдером идентификации,
сопоставление ролей и проверки доступа на уровне операций уже встроены в Master. Вы настраиваете своего провайдера
и политику доступа через готовые механизмы, а не пишете и сопровождаете интеграцию авторизации самостоятельно.

Axelix Master также готов к развёртыванию в виде автономного JAR со встроенными UI и MCP-сервером, официального Docker-образа
или официального Helm-чарта. См. [Настройка Master](../setting-up-master-ui/configuring-master/configuring-master.mdx).
В каждое управляемое приложение добавляются стартер и плагин сборки Axelix.

## Более глубокая диагностика и управление внутри приложения

SBA прежде всего представляет возможности управления, которые предоставляют стандартные эндпоинты Spring Boot и
Spring Cloud Actuator. Эта модель описана в его [руководстве по установке](https://docs.spring-boot-admin.com/3.5.1/docs/installation-and-setup/).
**Это существенно ограничивает глубину диагностики и управления, доступную в SBA из коробки:** он может показать
только те данные и предложить только те действия, которые предоставляют нативные эндпоинты.

Во время инцидента этих данных часто недостаточно, чтобы понять, что произошло внутри приложения. Например, список задач не объясняет,
почему конкретное выполнение завершилось ошибкой и не дает перевыполнить job если таковое требуется.
Расширения могут закрыть эти пробелы, но дополнительный код в приложении и консоли придётся писать и сопровождать вашей команде.

[Spring Boot Starter](../setting-up-spring-boot-service/spring-boot-starter/what-is-spring-boot-starter.mdx) Axelix
собирает дополнительные данные о работающем приложении и реализует действия за пределами стандартных эндпоинтов.
Одни механизмы обогащают данные Actuator, другие непосредственно отслеживают поведение приложения.
Поэтому в том же процессе отладки Axelix позволяет получить более подробные ответы и больше возможностей управления.

:::note[Планируемый отказ от собственных Actuator-эндпоинтов]
Сейчас стартер предоставляет собственные Actuator-эндпоинты `axelix-*`. Они открывают возможности за пределами
стандартного Actuator API. В [задаче #1858](https://github.com/axelixlabs/axelix/issues/1858) отслеживается планируемый
переход на независимые API Axelix из-за влияния внешней конфигурации, вопросов безопасности, ограничений абстракций
Actuator и переносимости. Устройство нового API ещё обсуждается. Это планируемое изменение, а не текущий транспорт.
:::

### Запланированные задачи и их выполнения

Список cron-выражений — только начало исследования запланированной задачи. Axelix записывает выполнения задач,
включая длительность и ошибки, чтобы можно было разобраться в результатах запуска. Задачу также можно запустить вручную,
включить или отключить, изменить cron-выражение, fixed delay или fixed rate без передеплоя.
См. [Запланированные задачи](../features/spring-framework/scheduled-tasks.mdx).

### Временная смена уровней логирования на нескольких репликах

Когда проблема может возникнуть на любой реплике, менять настройки каждого инстанса по очереди неудобно.
Axelix позволяет сменить уровень логгера на выбранных инстансах одного приложения на ограниченное время.
Когда оно истечёт, прежний уровень восстановится автоматически. Уровни групп логгеров тоже можно менять на нескольких
инстансах, а временные уровни доступны для отдельных логгеров.
См. [Логгеры](../features/insights/loggers/loggers.mdx).

### Действующие значения свойств и использующие их бины

Свойство в `application.yaml` не обязательно определяет значение, которое использует работающее приложение.
Axelix показывает источник с наивысшим приоритетом и значения, подавленные источниками с более высоким приоритетом.
Он связывает свойства с бинами, использующими `@Value` и `@ConfigurationProperties`, и показывает привязанные значения конфигурации.

Чтобы исследование конфигурации помогало находить ошибки, Axelix отмечает известные опасные действующие значения
и свойства, помеченные устаревшими в метаданных конфигурации Spring Boot. Чувствительные значения защищены правами
доступа и маскированием. См. [Свойства](../features/spring-framework/properties.mdx) и
[Configuration Properties](../features/spring-framework/configuration-properties.mdx).

### Бины и причины их создания

Axelix дополняет список бинов контекстом: зависимостями, источником создания, qualifiers, типом прокси и ссылками
на соответствующую автоконфигурацию. Вместе с отчётом об условиях это помогает понять, почему Spring создал бин
и какую роль он играет в приложении. См. [Бины](../features/spring-framework/beans.mdx) и
[Условия](../features/spring-framework/conditions.mdx).

### Выполнения транзакций и антипаттерны

Axelix отслеживает выполнения транзакций и собирает их среднюю, минимальную и максимальную длительность.
Он обнаруживает блокирующие вызовы через `RestTemplate` внутри транзакций, N+1 запросы при ленивой загрузке
и пагинацию Hibernate в памяти, предоставляя детали для поиска проблемы в коде. Это диагностика на уровне приложения,
выходящая за рамки стандартного Actuator. См. [Контроль транзакций](../features/spring-framework/transaction-control.mdx).

## От отдельных сервисов к развитию экосистемы

Отладка работающих приложений — одна из задач Axelix. Командам также нужно понимать, от чего зависит экосистема
и как она развивается.

- **Миграции Java и Spring Boot.** [Spring Portfolio](../ui-guide/dashboard/spring-portfolio.mdx) и
  [Languages Profile](../ui-guide/dashboard/languages-profile.mdx) показывают версии Spring и Java в приложениях,
  чтобы команды могли отслеживать ход миграции.
- **Состояние зависимостей.** [Дашборд Dependency Health](../ui-guide/dashboard/dependency-health.mdx)
  показывает использование библиотек, их версии и статус поддержки во всей экосистеме.
  [Анализ зависимостей](../features/insights/dependencies-analyzer.mdx) отдельного инстанса помогает исследовать библиотеки конкретного приложения.

Эти представления связывают проблему одного сервиса с работой во всей экосистеме: например, заменой неподдерживаемой
библиотеки или переводом приложений на поддерживаемое поколение Spring Boot.

## AI-native сценарии

Axelix рассчитан на непосредственную работу инженеров и AI-агентов с диагностикой приложений.
Встроенный MCP-сервер предоставляет агентам исследование состояния приложений, метаданные, обнаруженные проблемы
слоя персистентности и доступные операции во время работы сервисов. Проверки доступа встроены в Master.
Агент может найти сервис, изучить его бины и конфигурацию, исследовать обнаруженные проблемы персистентности
или изменить уровень логгера через инструменты.

В [каталоге MCP-инструментов](../setting-up-master-ui/mcp/mcp-tools.mdx) перечислены текущие возможности.
Пока он охватывает не все операции UI. AI-native направление платформы предполагает доступность анализа и управления
для агентов так же, как для людей.

SBA теперь тоже описывает [экспериментальную интеграцию MCP](https://docs.spring-boot-admin.com/4.1.4/docs/mcp/).
Поэтому различие заключается в глубине и охвате доступной информации и действий, а также во встроенной модели прав
Axelix и более широких возможностях работы с экосистемой.

## Сравнение возможностей

Ниже сравниваются стандартные сценарии SBA и возможности, входящие в Axelix OSS. SBA можно расширять,
а набор возможностей зависит от версии. Его новая интеграция MCP указана явно, а не представлена как отсутствующая.

| Область | Spring Boot Admin | Axelix |
|------|-------------------|--------|
| Состояние приложения, метрики, конфигурация, логгеры | Стандартное управление через Actuator | Включено, с дополнительными данными и управлением во время работы приложения |
| Управление пользователями и RBAC на уровне операций | Самостоятельная реализация и сопровождение интеграции IAM и правил авторизации через Spring Security | Встроенные локальные пользователи, сопоставление ролей OIDC и authorities |
| Аутентификация при обращении к сервисам | Настройка безопасности Actuator и учётных данных | Встроенная JWT-аутентификация между Master и стартером |
| Временные уровни логирования с автоматическим восстановлением на нескольких репликах | — | Включено ([Логгеры](../features/insights/loggers/loggers.mdx)) |
| Исследование свойств | Environment и configuration properties Actuator | Действующие и подавленные значения, связи с бинами, метаданные устаревания, проверка опасных значений |
| Исследование бинов | Дескрипторы бинов Actuator | Расширенные данные об источнике, qualifiers, прокси и связях с автоконфигурацией |
| Запланированные задачи | Список задач Actuator | История выполнений, длительность, ошибки, ручной запуск, включение/отключение, изменение расписания |
| Диагностика транзакций | — | Статистика выполнения и обнаруженные антипаттерны |
| Управление кешами | Стандартное исследование и очистка через Actuator | Исследование, очистка, включение/отключение во время работы ([Кеши](../features/spring-framework/caches.mdx)) |
| Отслеживание миграций Java / Spring Boot | — | Spring Portfolio и Languages Profile для всей экосистемы |
| Статус поддержки зависимостей | — | Анализ отдельного инстанса и дашборд экосистемы |
| Доступ AI-агентов | Экспериментальный MCP-модуль в новых версиях SBA | Встроенный MCP-сервер с исследованием приложений, диагностикой и доступными действиями |
| Готовый к запуску дистрибутив | Сборка и настройка приложения SBA | Автономный JAR, официальный Docker-образ, официальный Helm-чарт |
