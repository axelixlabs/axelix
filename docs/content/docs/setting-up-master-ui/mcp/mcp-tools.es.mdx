Cada entrada incluye el nombre de la herramienta, las etiquetas de anotación que anuncia, el estado de activación, los roles autorizados a invocarla y una
descripción breve de su función. El mismo catálogo está disponible en el navegador, en la [pantalla
MCP](../../ui-guide/mcp.mdx); esta página es la referencia para los operadores que planifican quién debe poder
invocar cada herramienta.

La lista presupone que el servidor MCP está activado (`axelix.master.mcp-server.enabled=true`, valor predeterminado). Si la propiedad se
establece en `false`, el servidor no se registra, ninguna de las herramientas siguientes es accesible y el enlace **MCP** se
oculta en la interfaz. Consulte [Configuración del servidor MCP](../configuring-master/configuring-master.mdx#mcp-server).

## Estado de las herramientas [#tool-state]

Todas las herramientas siguientes se incluyen en Master y se registran en el servidor MCP al iniciar. No existe un interruptor de activación o desactivación
por herramienta: el catálogo queda fijado en la compilación. Una herramienta solo deja de ser accesible si se desactiva el propio servidor MCP
o si el proceso de Master no está en ejecución. En el [catálogo de la interfaz](../../ui-guide/mcp.mdx#the-tool-catalog), el indicador de estado
de cada tarjeta refleja ese registro en tiempo real: verde cuando el servidor ha registrado la herramienta y rojo cuando
no está disponible.

## Etiquetas de las herramientas [#tool-tags]

Cada herramienta declara cuatro etiquetas de anotación booleanas que indican a los clientes MCP qué efectos secundarios pueden esperar. Las etiquetas
siguientes son los valores que declaran las herramientas de Axelix: son indicaciones para el agente que llama, no comprobaciones de autorización impuestas por
Master.

- **read-only**: la herramienta no cambia ningún estado en la instancia Spring Boot de destino.
- **idempotent**: invocar la herramienta varias veces con los mismos argumentos tiene el mismo efecto que hacerlo una vez.
- **destructive**: la herramienta puede eliminar datos o aplicar cambios que no pueden deshacerse desde la interfaz.
- **open-world**: la herramienta accede a recursos fuera de Master y de las instancias Spring Boot registradas.

## Control de acceso por roles [#role-gating]

El filtro MCP (`McpAuthorizationFilter`) autentica al agente del mismo modo que la interfaz autentica una sesión de navegador.
Consulte [Autenticación del servidor MCP](../authentication/authentication.mdx#mcp-server-authentication) para conocer los esquemas de
credenciales.

## Catálogo [#catalog]

:::info
El catálogo siguiente contiene el conjunto actual de herramientas MCP distribuidas con Master. Se están desarrollando más herramientas y la
lista crecerá en futuras versiones; se añadirán nuevas entradas aquí.
:::

La columna **Desde** indica la versión de Axelix Master que incluyó por primera vez la herramienta. `1.0.0` es la primera versión de Axelix, por lo que una
herramienta marcada con `1.0.0` existe desde el principio. Una versión marcada como _próxima_ aún no se ha publicado: la herramienta
estará disponible en la siguiente versión de Axelix, tanto si es menor como si es principal.

### Instancias [#instances]

La única herramienta de este grupo devuelve el registro completo de instancias Spring Boot gestionadas por Master. Es el punto de partida de
cualquier tarea que empiece por "encontrar el servicio por nombre y obtener su `instanceId`": todas las demás herramientas necesitan ese
`instanceId`.

Relacionado: [Guía de la interfaz Wallboard](../../ui-guide/wallboard.mdx).

#### `getWallboard` pasa a llamarse `getInstances` [#getwallboard-is-renamed-to-getinstances]

<ReleasedInNotice version="1.3.0" />

Hasta Axelix 1.2.x inclusive, esta herramienta se llamaba `getWallboard`. Desde Axelix 1.3.0, se llama
`getInstances` y `getWallboard` ya no existe. El comportamiento, los parámetros y la respuesta de la herramienta no cambian.

Los agentes de IA descubren las herramientas del servidor MCP al conectarse, por lo que adoptan el nuevo nombre automáticamente. Si invoca la herramienta
directamente por nombre, por ejemplo desde scripts propios o instrucciones de un agente, sustituya `getWallboard` por
`getInstances`.

### Análisis de persistencia [#persistence-insights]

Problemas de persistencia detectados por Axelix en la capa de acceso a datos de una aplicación. A diferencia de todas las herramientas anteriores, estas se identifican mediante
las coordenadas de compilación de la aplicación —`groupId` y `artifactId` (la G y la A de la coordenada GAV), ambas
obligatorias— en lugar de mediante un `instanceId`, y leen la instantánea registrada de la aplicación en vez de sondear una instancia
en ejecución.

Relacionado: [Transaction Control](../../features/spring-framework/transaction-control.mdx).
