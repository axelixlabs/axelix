# Часто встречающиеся проблемы

На этой странице описаны наиболее часто встречающиеся проблемы, возникающие при установке и настройке Axelix.

## Ошибка аутентификации (401) при обращении к эндпоинтам Axelix

**Симптом проблемы:** на стороне Master при обращении к управляемому сервису возинкает ошибка 401, несмотря на то, что на стороне управляемого сервиса открыт
доступ к эндпоинтам Axelix в application.yaml и корректно сконфигурирован Spring Security. 

**Причина возникновения:** в случае, если на управляемом сервисе включена аутентификация/авторизация с использованием IAM-решения (чаще всего Keycloak) и соответствующим образом 
настроен Spring Security, все входящие клиентские запросы обрабатываются фильтром BearerTokenAuthenticationFilter. Это касается всех эндпоинтов, в том числе и тех, которые были 
открыты через установку `management.endpoints.web.exposure.include`, при этом логика работы фильтра выглядит следующим образом:

```
[ Client App ]
      │
      │ 1. HTTP Request + Authorization Header ("Bearer <token>")
      ▼
┌────────────────────────────────────────────────────────┐
│               Application Filter Chain                 │
│                                                        │
│   ┌──────────────────────────────────────────────┐     │
│   │  [1] Bearer Token Authentication Filter      │     │
│   │      (e.g., Spring OncePerRequestFilter)     │     │
│   └──────────────────────┬───────────────────────┘     │
│                          │                             │
│                          │ 2. Read Authorization Header│
│                          ▼                             │
│               { Has "Bearer " prefix? }                │
│                 /                  \                   │
│         [No]   /                    \  [Yes]           │
│               ▼                      ▼                 │
│     ┌──────────────────┐   ┌───────────────────┐       │
│     │ Reject or Pass   │   │ 3. Extract Token  │       │
│     │ to Next Filter   │   └─────────┬─────────┘       │
│     │ (for public EP)  │             │                 │
│     └──────────────────┘             │                 │
│                                      ▼                 │
│                            [2] Token Validator         │
│                            ┌─────────┬─────────┐       │
│                            │ Check Expiration  │       │
│                            │ Verify Signature  │       │
│                            └─────────┬─────────┘       │
│                                      │                 │
│                        4. Validate   │ 5. Retrieve     │
│                        & Cache Keys  │    Public Keys  │
│                                      ▼                 │
│                        ┌──────────────────────────┐    │
│                        │ [3] Identity Provider    │    │
│                        │     (Auth0, Keycloak)    │    │
│                        └──────────────────────────┘    │
│                                      │                 │
│                                      │ 6. Token Valid  │
│                                      ▼                 │
│                            [4] Security Context        │
│                            ┌───────────────────┐       │
│                            │ Populate Principal│       │
│                            │ & Authorities     │       │
│                            └─────────┬─────────┘       │
│                                      │                 │
│                                      │ 7. Proceed      │
│                                      ▼                 │
│                        ┌──────────────────────────┐    │
│                        │    Other Web Filters     │    │
│                        └─────────┬────────────────┘    │
└──────────────────────────────────┼─────────────────────┘
                                   │
                                   │ 8. Forward Authorized Request
                                   ▼
                        ┌──────────────────────────┐
                        │   Protected API Resource │
                        │      (Controller)        │
                        └──────────────────────────┘
```

Как видно из диаграммы, фильтр всегда выполняет валидацию токена аутентификации в случае, если он присутствует в клиентском запросе, даже если запрос выполняется к открытому 
ресурсу. В описанной ситуации запрос со стороны Master к эндпоинту управляемого сервиса (```/actuator/axelix..```) будет содержать токен аутентификации Master, который не пройдет валидацию на имеющемся 
IAM-продукте и фильтр вернет ошибку 401. 

**Решение:** На текущий момент можно использовать workaround с исключением эндпоинтов Axelix из соответствующей цепочки фильтров:

```
@Bean 
public WebSecurityCustomizer webSecurityCustomizer() { 
  return (web) -> web.ignoring().requestMatchers("/actuator/axelix**"); 
}
```
